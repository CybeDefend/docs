## How Cybe Analysis Works

### 1. Code Parsing & Knowledge Graph

When you enable Cybe Analysis, CybeDefend parses your entire codebase into a proprietary **knowledge graph**. This graph captures:

- Code structure and relationships
- Data flows between functions and files
- Dependencies and their usages
- Business logic patterns

This knowledge graph becomes the foundation for all AI-powered analysis.

### 2. AI Agent Analysis

Using custom tools built specifically to interact with the knowledge graph, the Cybe AI agent:

- Analyzes detected vulnerabilities in full context
- Traces data flows to determine real exploitability
- Evaluates business impact based on code usage
- Provides expert-level assessments and recommendations

## Configuration

### Enable Cybe Analysis

<Frame>
  <img src="/images/agent-ai/cybe-analysis-enabled.png" alt="Enable Cybe Analysis in Project Settings" style={{ borderRadius: '0.5rem' }} />
</Frame>

1. Navigate to **Project Settings**
2. Find the **Cybe Analysis** section
3. Toggle **Enable Cybe Analysis**
4. Save your settings

<Warning>
Enabling Cybe Analysis requires code parsing, which stores your code in your selected sovereign cloud (EU or US) to ensure zero hallucinations and optimal performance.
</Warning>

### Select Vulnerability Groups

<Frame>
  <img src="/images/agent-ai/vulnerability-groups-selection.png" alt="Select SAST Vulnerability Groups" style={{ borderRadius: '0.5rem' }} />
</Frame>

For **SAST scanning**, you can select specific vulnerability groups to analyze:

- SQL Injection
- LDAP Injection
- Cross-Site Scripting (XSS)
- Path Traversal
- Command Injection
- And more...

**Why selective scanning?** This allows you to focus on vulnerabilities relevant to your application and optimize analysis time.

## Using Cybe Analysis

### Automatic Vulnerability Analysis

Once configured, Cybe Analysis automatically:

1. **Scans selected vulnerability groups** when a scan is triggered
2. **Analyzes each finding** using the knowledge graph for context
3. **Adds detailed comments** to vulnerabilities like a security expert would
4. **Updates vulnerability status** (confirmed, false positive, etc.)

### Following an Analysis in Progress

Cybe Analysis runs alongside and after the scanners. While they work, CybeDefend indexes your code; once the SAST and IaC scanners have finished, the agent works through their findings. Scanner results reach the results pages as soon as the scanners finish, so you can start triaging before the analysis ends.

The **Scan progress** panel on the results pages shows where the analysis is:

| Stage | What is happening |
|-------|-------------------|
| **Indexing code** | Your code is being parsed into the knowledge graph the agent reasons over. |
| **Waiting for scanner results** | At least one SAST or IaC scanner is still running. |
| **Waiting for an AI slot** | The analysis is queued. The panel shows its approximate position. |
| **AI analysis** | The agent is reviewing the findings, with the number it has covered so far. |

### Priority Assignment

If **vulnerability triage** is enabled in settings:

- Cybe Analysis assigns **priority levels** (Critical, High, Medium, Low)
- Prioritization considers:
  - Exploitability in your specific context
  - Data sensitivity
  - Exposure to external inputs
  - Business impact

## Understanding the Results

### Vulnerability Comments

Each analyzed vulnerability receives a comment from Cybe

<Frame>
  <img src="/images/agent-ai/false-positive-detection.png" alt="Cybe Analysis False Positive Detection" style={{ borderRadius: '0.5rem' }} />
</Frame>

### In an Exported Report

The project's **OWASP Top 10** and **CWE Top 25** reports carry the analysis too, when you generate them with **Detailed Report** on (`detailed=true` on the API). Under each finding the agent reviewed, the HTML and PDF reports print a Cybe Analysis box: the agent's verdict, a short *Why it matters*, and the fix steps it proposed. A finding the agent did not review shows no box.

Which findings carry the box: every finding still open, plus critical and high findings whatever status you gave them. The organization and team aggregated reports do not carry it.

### When an Analysis Stops Early

An analysis can stop before it has reviewed every finding, or end without reviewing any. The **Scan progress** panel states why, and the findings it did review keep their verdicts.

| What the panel says | What it means |
|---------------------|---------------|
| There were no SAST or IaC results to analyze | The scan produced no SAST or IaC findings, so there was nothing to review. |
| AI result improvement is turned off for this project | **Enable Cybe Analysis** is off in the project's settings. |
| Your organization's analysis quota is used up | The organization has no Cybe Analysis credits left — see [AI Usage Tracking](/latest/plateform-overview/plan-&-pricing/ai-usage-tracking). |
| The code could not be indexed · Indexing the code took longer than allowed | The analysis needs your code indexed first. Your scanner findings are unaffected. |
| No AI slot came free within the allowed wait · The analysis ran past its time limit | The analysis stopped before it finished. |
| The analysis ran into an error · The AI analysis service could not be reached | The analysis failed. Your scanner findings are unaffected. |

Triggering a new scan runs the analysis again.

### When an Analysis Is Out of Date

A verdict describes the finding as it stood when the analysis ran. On SAST, IaC and CI/CD findings, CybeDefend flags a verdict that has been overtaken:

| Flag | When it appears |
|------|-----------------|
| **This agent analysis predates the latest security context** | You changed the project's security context after the verdict was produced |
| **This agent analysis dates from a previous scan** | A later scan of that scanner type ran after the verdict was produced |

Where you see it:

- An amber warning badge next to the analysis badges on the finding's row in the results list, with the reason as tooltip.
- A banner on the finding detail, with a **Re-run agent analysis** button that queues a fresh analysis for that finding.
- On the SAST, IaC and CI/CD results pages, a banner grouping the analyses that predate the latest security context, with a **Re-run all** button.

## Requirements

- Project must be created in CybeDefend
- Code parsing must be enabled (automatic when Cybe Analysis is enabled)
- SAST scanner must be enabled for the project
- Sufficient Cybe Analysis credits in your subscription
