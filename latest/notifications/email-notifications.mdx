---
title: "Email Notifications"
description: "Which emails CybeDefend sends, who receives each one, and how the Email Notifications toggle turns them off."
---

CybeDefend sends security email from two families: the **periodic reports**,
which go to everyone with access to the projects they cover, and the
**per-project alerts**, which go to the organization creator. One setting turns
both off.

---

## The Toggle

**Profile → Email Notifications** controls whether you receive security email.
It is on by default.

Through the API, it is the `notification` field on your own profile:

```bash
curl -X PATCH https://api-eu.cybedefend.com/user/profile \
  -H "Authorization: Bearer $CYBEDEFEND_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"notification": false}'
```

Use `https://api-us.cybedefend.com` for the US region.

---

## What the Toggle Covers

| Email | Sent to | Gated by the toggle |
|-------|---------|---------------------|
| Weekly report | Every user who can access a project in the report | Yes, per recipient |
| Monthly report | Every user who can access a project in the report | Yes, per recipient |
| Daily critical alerts | Every user who can access a project in the report | Yes, per recipient |
| Zero-day alert | The organization creator | Yes |
| Scan complete report | The organization creator | Yes |
| Organization invitation | The invited address | No — transactional |
| Welcome email | The new account | No — transactional |

A periodic report is built per recipient: it covers only the projects that
recipient is allowed to see, so two people in the same organization can receive
the same weekly report describing different projects.

<Warning>
  **Behaviour change.** The zero-day alert and the scan complete report
  previously ignored the toggle — an organization creator who had turned Email
  Notifications off still received them. They are now gated like every other
  report. If you turned the toggle off and were relying on those two emails
  still arriving, turn it back on.
</Warning>

<Note>
  Only an explicit opt-out silences an email. An account whose preference has
  never been recorded keeps receiving security email rather than being muted by
  default.
</Note>

---

## Choosing Per Channel

The email toggle is all-or-nothing. To keep some alerting while turning email
off, connect a [Slack workspace](/latest/notifications/slack) — Slack is
connected at the organization level, mapped to a channel per project, and is
unaffected by this setting.
